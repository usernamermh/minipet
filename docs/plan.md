# 桌面宠物重构计划 v4

更新时间：2026-05-23

## 目标

将当前项目从“窗口里放一个宠物面板”的实现，重构为真正的透明无边框桌宠：

- 主视觉只保留宠物本体，不出现传统应用窗口边框
- 主窗口透明、置顶、跳过任务栏，常驻桌面
- 交互改为宠物本体点击、拖拽、托盘菜单、气泡输入
- 保留最小可运行的状态系统、持久化和 LLM 对话链路

## 问题回顾

当前代码存在以下根本性问题：

1. 主进程、preload、渲染层 IPC 命名不一致，核心交互链路断裂
2. 生产环境加载的是占位测试页，不是桌宠界面
3. 现有 UI 是大面板式布局，不符合桌宠目标
4. 状态衰减、阶段成长、托盘命令和主动行为多为硬编码或占位
5. 渲染逻辑同时存在 TS 原型和 `public/app.js` 旧脚本，维护成本高

## 重构原则

1. 先打通最小可运行链路，再补高级能力
2. 主窗口只承载宠物与气泡，不再承载完整设置面板
3. 主进程作为状态与后端桥接中心，渲染层只做表现与交互
4. 旧代码可暂时保留，但不再作为启动主链路
5. 所有新增链路统一使用一套 IPC 命名

## 新方案

### 1. 窗口形态

- Electron 透明无边框窗口
- `alwaysOnTop + skipTaskbar + transparent + frame:false`
- 默认尺寸贴合宠物活动区域，而不是整页控制台
- 页面背景全透明，仅显示宠物精灵、状态气泡和输入浮层

### 2. 交互形态

- 左键点击宠物：抚摸并展开聊天输入
- 拖拽宠物：移动桌宠位置
- 托盘菜单：喂食、清洁、陪玩、睡觉、显示/隐藏、退出
- 文本输入：通过底部小浮层发给后端，返回结果显示为对话气泡

### 3. 最小功能闭环

- 本地 JSON 状态持久化
- 宠物属性：饥饿、清洁、精力、心情、等级、经验
- 基础交互：喂食、清洁、抚摸、陪玩、睡觉
- 年龄阶段：幼年 / 成长期 / 成年期
- Python FastAPI 对话后端
- 本地降级回复，保证后端不可用时也能对话

### 4. 本轮不强求一次做完的内容

- 20 种完整精灵动画资源接入
- 点击透明穿透精确到宠物非透明像素
- 微信好友系统
- 低占用精细性能调优
- 复杂记忆压缩策略优化

## 代码重构步骤

### 阶段 A：文档与入口统一

- 重写 `docs/plan.md`、`docs/bone.md`、`docs/project-summary.md`
- 明确新主链路：`main -> preload -> public/index.html -> dist/renderer/app.js`

### 阶段 B：主进程重构

- 统一 IPC
- 增加主进程状态更新与广播
- 增加聊天代理和本地降级回复
- 修复托盘命令真实生效

### 阶段 C：窗口与渲染重构

- 删除大面板式 HTML
- 改为透明场景 + 宠物 Canvas + 气泡层 + 输入浮层
- 用新的 `app.ts` 承接交互

### 阶段 D：状态最小闭环

- 统一状态衰减
- 统一等级成长与阶段推导
- 状态变更后持久化并推送到渲染层

### 阶段 E：验证

- TypeScript 构建
- Python 语法检查
- 启动链路验证

## 验收标准

- 启动后看到的是透明桌宠，而不是面板窗口
- 托盘交互可以真实修改宠物状态
- 点击宠物可弹出输入浮层并完成一次对话
- 状态可以保存并在重启后恢复
- 后端失败时仍有本地回复，不影响基本体验

## 当前实施优先级

1. 透明无边框桌宠主窗
2. 统一 IPC 与状态主链路
3. 气泡输入与对话返回
4. 托盘命令与基础互动
5. 再逐步替换旧动画/旧模块
