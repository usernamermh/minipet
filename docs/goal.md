# 功能需求
1. 核心宠物生命周期系统
状态属性：实现（饥饿、清洁、精力、心情、等级/经验）五项基础属性，每项属性实时变化（如饥饿值每10分钟下降1点）。【状态转移参数要可配置，状态转移方案要有可扩展性】
交互指令：支持（喂食、清洁、抚摸、陪玩、睡觉）五项基础交互，每项交互可增加对应属性值。【状态转移参数要可配置，状态转移方案要有可扩展性】
宠物阶段：宠物分为幼年期（0-7天）→成长期（8-30天）→成年期（31天后），不同阶段外观、交互反馈、属性变化速率不同。【状态转移参数要可配置，状态转移方案要有可扩展性】
宠物成长：要求能够根据宠物和用户对话历史的长度和质量来让宠物进行成长，升级、加经验等等。【自拟一个成长方案】        
状态持久化存储：写入本地json文件作为持久化存储方案。
大模型交互：要求宠物能通过调用LLM与用户对话，宠物拥有与用户的记忆，作为上下文调用的背景。【要考虑上下文压缩与摘要】 
宠物能和用户对话，支持简洁的对话弹窗。

2. 交互与娱乐系统
动画：至少20种独立动画（吃饭、洗澡、睡觉、生气、飞翔、淘气等），动画切换平滑无卡顿。自行调研哪些网站可提供给相关素材，并将相关素材下载至resources目录，按照来源和宠物类型分好目录。
拖拽/点击反馈：支持鼠标拖拽宠物移动，支持LLM对话。
桌面模式：宠物常驻桌面角落，可随机走动、跳跃、打瞌睡；右键菜单提供喂食、清洁等快速操作。
语音/音效：宠物发出8种以上语气词（饥饿、开心、撒娇、困倦等），支持静音开关；交互动作伴有专属音效。
每隔一定时间，如果用户未和宠物互动，宠物应当随机选择一个话题主动发起交流。

3. 技术架构与性能需求
平台支持：Windows（Electron + WebView），需适配不同屏幕DPI与任务栏位置。
资源管理：所有图片、动画帧、音效采用异步预加载，缓存总大小不超过50MB。
低占用模式：宠物闲置时CPU占用率<1%，动画帧率自动降为10fps；玩家交互时恢复30fps。

4. 社交与运营功能
好友拜访：可通过微信访问好友宠物，赠送体力或随机道具，点赞增加双方心情值。
